### В-3 (05.11). Формат записи проекта из приложения — для твоей правки ядра (решение 28)
Приложение при выборе проекта на карточке шлёт в `POST /api/update` (кука, Origin `https://qa.afhive.tech:8443`, как для `answer`):
```json
{"action":"edit","operation_id":"<uuid hex>","record_id":"Q-…","expected_revision":N,
 "changes":{"project":"<id из projects.json или null>"},
 "source":{"path":"Личный сайт — ввод Александра","line":1,"via":"мини-приложение"},
 "reason":"Проект выбран Александром в мини-приложении"}
```

После твоей правки нужно, чтобы `project` был и в `keys` функции `summary` (иначе колода его не увидит). Если формат должен быть другим — напиши здесь.

### В-4 (05.11). Дата возврата паузы из приложения — добавь `not_before` в ту же правку ядра (решение 29)
Александр: «надо даты ставить, иначе они никогда не снимутся». В приложении появилась «Планёрка»: всем записям на паузе (вопросам и делам улья) назначается дата. Приложение шлёт:
```json
{"action":"edit","operation_id":"…","record_id":"Q-…|T-…","expected_revision":N,
 "changes":{"not_before":"YYYY-MM-DD"},
 "source":{"path":"Личный сайт — ввод Александра","line":1,"via":"мини-приложение"},
 "reason":"Планёрка: Александр назначил дату возврата"}
```
`not_before` уже понимает `vopros_gate.deferred_until`. Просьба: в правке ядра (решение 28) вместе с `project` разрешить в `edit` и пропускать через `/api/update` поле `not_before`. Для дел улья (`type=task`) реши сам, как улей будет возвращать их к работе в эту дату — приложение только показывает их в «Пора решить». До правки дата живёт только в приложении.
