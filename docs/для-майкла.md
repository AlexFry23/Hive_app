**1. Код на VPS (с Мака, из свежей копии ветки)**
```
VPS=<твой ssh-адрес VPS, как в vps-bridge-sync>
rsync -a --delete app/    "$VPS":/opt/office-app/app/
rsync -a --delete web/    "$VPS":/opt/office-app/web/

```
Дальше на VPS:
```
find /opt/office-app/app /opt/office-app/web /opt/office-app/deploy -name __pycache__ -prune -exec rm -rf {} +
chown -R root:office-app /opt/office-app/app /opt/office-app/web /opt/office-app/deploy
chmod -R u=rwX,g=rX,o= /opt/office-app/app /opt/office-app/web /opt/office-app/deploy
```

**2. Настройки `/opt/office-app/.env`** (образец — `deploy/env.example`)
- `BOT_TOKEN` — токен нового бота приложения (из секретов Мака).
- `ALLOWED_USER_ID` — Telegram id Александра = chat_id его лички (`secrets/telegram-chat-id`).
- Остальное — как в образце.
```
install -o root -g root -m 0600 /dev/null /opt/office-app/.env   # затем вписать значения
```
- `projects.json` (решение 19) должен читаться службой: `chown office-app:office-app /opt/office-app/data/projects.json` (или права 0644), и так же при каждом обновлении в 21:30.

**3. Служба**
```
install -o root -g root -m 0644 /opt/office-app/deploy/office-app.service /etc/systemd/system/office-app.service
systemctl daemon-reload
systemctl enable --now office-app
```

**4. Проверки после**
```
systemctl is-active office-app                               # active
curl -s http://127.0.0.1:18780/health
#   ожидается: "ok": true, "bot_token": true, "allowed_user": true,
#   "registry_key": true, "registry": true, "menu_button": true

# цикл кодов сайтов из шага 0 — коды совпадают с «до»
```

Если `registry` false — пришли строку `реестр: …` из журнала. Если `menu_button` false — строку `кнопка меню: …`.

**Откат**
```

rm /etc/systemd/system/office-app.service && systemctl daemon-reload

rm -rf /opt/office-app/app /opt/office-app/web /opt/office-app/deploy /opt/office-app/.env
```
