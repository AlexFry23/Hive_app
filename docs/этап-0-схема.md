# Этап 0. Схема: приложение рядом с ульем

Дата: 01.11.2026. Источник: архив «Улей для приложения - разведка» (файл «Разведка этап 0.md» и копии файлов улья), перепроверено по копиям кода. На Маке и VPS ничего не менялось.

С учётом решения 8 (отдельный бот) схема разведки уточнена: токен бота Майкла приложению не нужен.

## Схема

```
Телефон (Telegram) ── кнопка меню НОВОГО бота
        │
        ▼
https://<поддомен>.afhive.tech:8443        новый блок в /opt/caddy/Caddyfile; DNS не нужен (wildcard)
        │
        ▼
служба приложения 127.0.0.1:<порт>         новая, /opt/office-app, свой пользователь
  ├─ проверка initData токеном НОВОГО бота (.env), пускает только Александра
  ├─ своя база SQLite: отсрочки, «пролистано», проекты, задачи, напоминания
  ├─ чтение/ответ ──► реестр 127.0.0.1:18768 (/api/state, /api/record, POST /api/update)
  │                   кука hive_session (HMAC ключом access.key) + Origin https://qa.afhive.tech:8443
  └─ напоминания ──► Bot API нового бота, напрямую в личку

Реестр ─► answer_notifications ─► outbox-telegram ─► мост Майкла ─► «Принял ответ…» (штатно, без правок)
Мосты hive-bridge-michael / -oscar, талоны, сторожа — не трогаются.
```

## Что придётся изменить на сервере (каждое — после «да», с откатом)

| № | Изменение | Откат |
|---|---|---|
| 1 | Блок поддомена в Caddyfile, `caddy validate`, `caddy reload` хостовому процессу | вернуть копию Caddyfile, `caddy reload` |
| 2 | Каталог `/opt/office-app`, служба `office-app.service`, отдельный пользователь | `systemctl disable --now`, удалить каталог и юнит |
| 3 | Доступ к `access.key` реестра (сейчас root, 0600): группа на чтение только этого файла | вернуть владельца и права |
| 4 | Кнопка меню нового бота (`setChatMenuButton`) — только вызов Bot API | вызов с `default` |
| 5 | Таймер напоминаний приложения | `systemctl disable --now` |

Ядро реестра, мосты, файлы улья — не меняются. Отсрочки и «вернуть через 3 дня» хранятся в базе приложения.

## Что может сломаться

1. Перезагрузка Caddy задевает все сайты улья (панель «Вопросы», файлы, GIS и др.). Защита: копия, `caddy validate`, проверка всех адресов после.
2. Конфликт версий записи с агентами (HTTP 409). Защита: `operation_id`, `expected_revision`, обратное чтение, повтор после перечитывания.
3. Квитанция «Принял ответ» приходит, только если `author="Александр"` и `source.path="Личный сайт — ввод Александра"`. Иначе агенты увидят ответ только из реестра, без квитанции.
4. Чтение `access.key` даёт службе приложения полный доступ к HTTP-API реестра (те же права, что у панели).
5. `/api/state` отдаёт все записи (~1041, файл 15 МБ) — нужен кэш.
6. Служебная запись канарейки (`HIVE_REGISTRY_HIDDEN`) — из списков уже скрыта; по прямому id отдаётся, не запрашивать.
7. Порт 8443 в адресе мини-приложения на телефоне не проверен — первая проверка этапа 1.
8. «Нет» и «Снять» не имеют точных действий в реестре: ближайшие — `answer` с текстом «Нет» и `withdraw_question` (→ archived). Нужно согласие Александра.
