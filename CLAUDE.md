# Офис — мини-приложение Telegram поверх улья Майкла

Этот файл Claude Code читает в начале каждой сессии. Здесь всё, что нужно знать о проекте. Если что-то здесь расходится со словами Александра в чате — главнее его слова; расхождение записать сюда в тот же ход.

## Кто заказчик и как с ним говорить

- Заказчик — Александр. Не программист. Пишет коротко, часто голосом.
- Всё по-русски: ответы, отчёты, комментарии в интерфейсе, сообщения коммитов.
- Форма ответа: первая строка — суть одной фразой. Если нужно его решение — отдельная строка «Нужно от тебя: …». Дальше не больше трёх коротких строк. Подробности — только по слову «подробнее».
- Без жаргона, кодов, путей к файлам и английского в ответах ему. Если без термина нельзя — одно пояснение в скобках.
- Не додумывать. Неясно — один короткий вопрос. Несколько вопросов — списком, неотвеченные не терять и вернуть позже.
- Не придумывать ему новых задач. Свои находки — отдельной строкой в конце с пометкой «Замечание».
- Работа дольше 5 минут — сразу написать, к какому времени будет готово (по Москве).

## Что строим

Мини-приложение Telegram (Telegram Mini App) — вместо Singularity, которым Александр не пользуется. Он живёт в Telegram, поэтому задачи, вопросы улья и напоминания должны быть там.

Три вкладки, по порядку: «Сегодня», «Ждёт меня», «Проекты». Главная по смыслу — «Ждёт меня».

### «Ждёт меня» — колода карточек, как в Тиндере

На карточке только то, что нужно от Александра: аватар агента, который спрашивает, имя агента, вопрос, метка проекта, поле для ответа.

| Действие | Что значит |
|---|---|
| Свайп вправо | «Да» |
| Свайп влево | «Нет» = «не сейчас»: отложить на 7 дней, карточка вернётся (решение 01.11, заменило «закрыть без последствий») |
| Свайп вверх | Отложить: выбор «через 1 день», «через 3 дня», «через 5 дней», «выбрать дату». В выбранный день карточка возвращается |
| Меню «⋯» вверху справа → «Снять» | Больше не спрашивать, забыть навсегда |
| Поле на карточке | Ответ текстом (и голосом — см. этап 5) |

- Карточка, которую Александр пролистал без ответа, возвращается через 3 дня (значение по умолчанию, должно настраиваться).
- Свайп вниз не используется.
- Пустая колода — картинка «всё отвечено».

### «Сегодня»

Напоминания и сроки на 7 дней вперёд от сегодняшнего дня включительно: если сегодня среда — до следующей среды, если четверг — до следующего четверга (решение Александра 01.11).

### «Проекты»

Список проектов → внутри задачи. Карточка задачи: название, проект, срок, кто делает. Задачи нигде сами не всплывают — их видно, только когда Александр заходит в проект.

### Голос

Наговаривать задачи можно двумя путями: прямо в приложении и через бота-расшифровщика в Telegram (текст Александр пересылает в улей). Оба пути попадают в одни входящие.

### Внешний вид

Пиксельная графика, офис с аватарками агентов. Картинки сгенерировал Александр, они лежат в `assets/raw/`. Аватары — собственные персонажи, не персонажи сериалов и не чужие бренды: в интерфейсе не использовать логотипы, названия и образы сериала «Офис».

## Как устроен улей (проверено разведкой этапа 0, 01.11.2026; подробности — архив «Улей для приложения - разведка», файл «Разведка этап 0.md»)

- Улей — приложение Munder Difflin на Маке Александра, рабочая папка `/Users/mac/hive`. Оркестратор — Майкл (god).
- Агенты на этаже сейчас: Michael (оркестратор), Pam (аренда квартир РДМ), Oscar (финансы: Дзен-мани, чеки, бюджет), Kevin (кодер). Dwight (ресерч и тяжёлые задачи) — был в архиве с 29.10, вернулся 02.11. Creed и Toby постоянными агентами не являются — это были разовые исполнители по Google Диску.
- Telegram: два бота улья (Майкла и Оскара), группа «Улей» с темами (Чат, Вопросы, Финансы, РДМ, Файлы). Мосты — службы `hive-bridge-michael` и `hive-bridge-oscar` на VPS (`/opt/hive-bridge/bridge`), получают сообщения опросом getUpdates, вебхуков нет. Рядом сторожа `hive-bridge-watchdog`, `hive-talon`, `hive-vygon`.
- Реестр вопросов — служба `hive-registry` на VPS: код в `/opt/hive-registry` (папка закрыта: 0700 root), данные — один JSON `/opt/landing/voprosy/voprosy_answers.json`. HTTP-API на 127.0.0.1:18768: `/api/state`, `/api/record`, `/api/search`, `POST /api/update`; снаружи `qa.afhive.tech:8443` за паролем Caddy и кукой. Запись — с `operation_id`, `record_id`, `expected_revision`; «сохранено» — только после обратного чтения (ошибка версии — HTTP 409). Ядро `registry_core.py` на Маке и на VPS — две разные версии; работающая — на VPS.
- Ответ, записанный в реестр, агентам приходит только квитанцией в личку Александру; прямого письма агенту нет. Действия «отложить до даты» в реестре нет.
- Веб-сервер — Caddy (не nginx) в docker-контейнере `caddy`; папка хоста `/opt/caddy` видна в нём как `/etc/caddy`, конфиг `/opt/caddy/Caddyfile`; проверка и перезагрузка — через `docker exec caddy caddy …` (уточнено Майклом 01.11; разведка ошибочно считала его процессом на хосте). Домен afhive.tech с wildcard DNS: любой поддомен уже указывает на сервер, новый DNS не нужен. HTTPS у служебных адресов на порту 8443.
- Общего механизма напоминаний на VPS нет: таймер `hive-razbor-reminders` шлёт четыре зашитых напоминания (все в прошлом).
- Singularity: Александр им не пользуется, но в улье `bin/napomni.py` и AGENTS.md ещё ставят туда напоминания.

- Никому, кроме Александра, ничего не отправлять.
- Папки Google Диска Александра, почту, деньги — не трогать, это не задача проекта. Исключение — чтение списка папок «01_ПРОЕКТЫ» (решение 13).

## Как работаем

- Один этап за раз. Перед этапом — короткий план и «да» Александра. В конце этапа — отчёт: что сделано, как проверить на телефоне, что дальше, и вопрос «продолжать / стоп».
- «Готово» — только после проверки на настоящем телефоне в Telegram (скриншот или его подтверждение), а не «по коду».
- После каждого законченного шага — коммит с понятным русским сообщением.
- Каждое изменение на сервере — строка в `ЖУРНАЛ.md`: дата, что сделано, как откатить.
- Решения, принятые в чате, — сразу сюда, в раздел «Решения Александра».

## Технические заметки (проверить по документации Telegram: https://core.telegram.org/bots/webapps)

- Мини-приложение — обычная веб-страница по HTTPS, открывается кнопкой бота (кнопка меню, кнопка под сообщением или прямая ссылка).
- Данные пользователя приходят в `initData`. Сервер обязан проверять подпись `initData` токеном бота и пускать только Александра.
- В Telegram свайп вниз сворачивает мини-приложение. Чтобы свайпы карточек не закрывали его, вызвать `Telegram.WebApp.disableVerticalSwipes()`.
- Есть вибрация на жест (`HapticFeedback`) и полноэкранный режим — использовать по желанию.
- Доступ к микрофону внутри Telegram на iPhone и Android не проверен — проверить на этапе 5 до того, как писать код записи голоса.
- Стек выбрать на этапе 0 и согласовать. Улей написан на Python — бэкенд на Python проще стыковать. Фронтенд — как можно проще, без тяжёлой сборки.
- Пиксельную графику масштабировать без сглаживания (`image-rendering: pixelated`).
